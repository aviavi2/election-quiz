# שאלון התאמה למפלגות

אתר סטטי בעברית: המשתמש עונה על 18 שאלות ומקבל דירוג של הרשימות שעמדותיהן המתועדות הכי קרובות לשלו. כל החישוב נעשה בדפדפן, ושום מידע לא נשמר ולא נשלח.

> **מצב הנתונים (13.10.2026):** האתר כולל 13 רשימות (אלה שעוברות את אחוז החסימה בסקרים), ויש עמדות עם מקור ל-12 מהן. חלקן מבוססות על מצע עדכני וחלקן על הסכמים קואליציוניים מ-2022. הפירוט המלא, כולל מה לא אומת ואילו מיפויים דורשים בדיקה, נמצא ב-[data/MISSING.md](data/MISSING.md). כדאי לקרוא אותו לפני פרסום.

## הרצה מקומית

האתר טוען קובצי JSON, ולכן צריך שרת סטטי (פתיחה ישירה של `index.html` מהדיסק לא תעבוד):

```
npx serve .
```

או `python -m http.server 8000`, ואז לפתוח את הכתובת שמודפסת.

## בדיקות

```
npm test
```

דורש Node 20 ומעלה, בלי תלויות להתקנה. רצות בדיקות האלגוריתם (`tests/scoring.test.js`) ובדיקות שלמות לנתונים (`tests/data.test.js`): לכל עמדה יש מקור והסבר, והערך שלה תואם אחת מתשובות השאלה.

## עדכון נתונים

**עמדות (`data/parties.json`)**: לכל רשימה `positions` לפי מזהה שאלה:

```json
"q1": { "value": 1, "source": "https://...", "note": "ציטוט מהמקור או הסבר קצר" }
```

- `value` חייב להיות אחד מערכי התשובות של אותה שאלה ב-`questions.json`. האתר מציג את נוסח התשובה הזו כעמדת הרשימה.
- `source` חייב להיות קישור `https` למקור ראשוני (מצע, הצבעה בכנסת, ראיון מתועד).
- כשהמקור אינו מצע עדכני (למשל הסכם קואליציוני או הצבעה), לציין ב-`note` את שם המסמך ואת התאריך שלו. האתר מציג את ה-`note` למשתמש.
- כשאין מקור: להשמיט את המפתח או לכתוב `"value": null`. העמדה לא תיכנס לחישוב.
- רשימה מדורגת רק אם יש לה עמדה ידועה בלפחות 5 מהשאלות שהמשתמש ענה עליהן (`MIN_SHARED_QUESTIONS` ב-`js/scoring.js`). רשימה שלא עומדת בסף מופיעה במסך התוצאות תחת "רשימות שאינן בדירוג".
- כדי להוסיף או להסיר רשימה, מוסיפים או מוחקים את האובייקט שלה ב-`parties`. רשימה בלי עמדות נכתבת עם `"positions": {}`.
- אחרי עדכון: לשנות את `updated` בראש הקובץ, לעדכן את `MISSING.md` ולהריץ `npm test`.

**שאלות (`data/questions.json`)**: המשתמש יכול לסמן כמה תשובות בשאלה, והציון נקבע לפי התשובה שסימן שהכי קרובה לעמדת הרשימה. לתשובה מסוג "להשאיר את המצב הקיים" אפשר להוסיף שדה `detail` שמסביר מהו המצב הקיים; הוא מוצג מתחת לתשובה. לכל שאלה `axis` שמתאר את שני קצוות הציר, ו-`answers` שמסודרות לאורכו עם `value` בין 2- ל-2+. שינוי של ציר או של ערכי תשובות מחייב לעבור מחדש על עמדות כל הרשימות באותה שאלה.

**נתוני דמה**: `"demo": true` בראש `parties.json` מציג באנר אזהרה באתר.

## פריסה

אין שלב build. מעלים את התיקייה כמו שהיא.

**GitHub Pages**: להעלות את הקבצים למאגר, ואז Settings ← Pages ← Deploy from a branch, ענף `main`, תיקייה `/ (root)`. כל הנתיבים באתר יחסיים, כך שהוא עובד גם תחת `username.github.io/repo-name/`.

**Netlify**: לגרור את התיקייה ל-app.netlify.com/drop, או לחבר את המאגר בלי build command ועם publish directory `.`.
